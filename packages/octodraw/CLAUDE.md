# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

octodraw is an Eraser.io-style diagram-as-code canvas, built as a **React library to be embedded in octonote.ai** (a commercial notes + canvas product). It is not a standalone app: storage, auth, sharing and collaboration belong to the host. Keep dependencies permissively licensed (MIT/Apache/EPL) because the host is commercial — this is why tldraw (paid production license) is not used.

The DSL is deliberately **syntax-compatible with Eraser's public diagram-as-code reference** (https://docs.eraser.io/docs/syntax) so Eraser code and LLM-generated Eraser code render here. Implement from the public docs only; never copy Eraser code or branding. octodraw-only extensions are optional properties (currently `collapsed`, `description`) so Eraser code stays valid. The visual style (white canvas, flat 1px cards with icon + centered title/subtitle, dashed top-level groups, open chevron arrowheads, blue "Expand" pill for drill-down, plain-text breadcrumbs) is modelled on Eraser's product pages.

## Commands

Node 24 is required (`.nvmrc`; the machine default may be older — run `nvm use` first). pnpm workspace.

```bash
pnpm install
pnpm dev                 # playground at http://localhost:5180
pnpm build               # dist/ for octodraw and octodraw-server (library builds)
pnpm dev:server          # Claude diagram route at http://localhost:5181/api/diagram (needs packages/octodraw-server/.env)
pnpm test                # vitest in packages/octodraw
pnpm typecheck           # tsc --noEmit in every workspace package
pnpm --filter octodraw icons   # regenerate src/icons/generated.ts after editing scripts/icon-catalog.mjs

# single test file / single test
pnpm --filter octodraw exec vitest run test/parse.test.ts
pnpm --filter octodraw exec vitest run -t "fans out to multiple targets"
```

## Layout

- `packages/octodraw` — the library. In the workspace `exports` point at the TypeScript source (the playground and octodraw-server consume it directly); `pnpm build` (Vite library mode: `index`, `collab`, `prompt` entries, icon catalogues as lazy chunks, dependencies and React external; then `tsc -p tsconfig.build.json` for declarations) writes `dist/`, and `publishConfig` swaps `exports` to `dist` in packed/published copies. Check a change to packaging with `pnpm pack` + a fresh consumer project. The dist bundles Eraser's icon artwork (no redistribution licence): don't publish publicly.
- `packages/octodraw-server` — the AI server route (`createDiagramHandler`, Fetch API `Request`/`Response`; `src/dev.ts` is a Node server for development, run with Node's built-in type stripping, so only erasable TypeScript there — `erasableSyntaxOnly` is on). It calls Claude (`claude-opus-5-5`, server-side fallback beta) with `ANTHROPIC_API_KEY` from the environment and streams text; it accepts only octodraw's own system prompts (`allowedSystemPrompts`) and caps messages, size and images. Mid-stream failures are sent in-band as `\n\n[octodraw-error] …`, which `httpDiagramModel` turns into an error. See its README for octonote (Next.js route example).
- `apps/octodraw-playground` (in octonote-ai) — Vite app (proxies `/api` to the server route; the assistant uses it when its status says `configured`, else a key stored in the browser, else the demo model): Monaco editor (custom `octodraw` Monarch language, light/dark themes and `icon:`/`color:` completions in `src/monaco.ts`) and `<OctoDiagram>`, with a Code | Both | Canvas switch (⌘\ collapses the editor), resizable divider and light/dark/system toggle. Loads Inter and JetBrains Mono via @fontsource.

## Pipeline (packages/octodraw/src)

Each stage is a pure function except the last; keep it that way so stages stay testable without a DOM.

1. **`dsl/parse.ts`** — `parseDiagram(source) → Diagram`. Line-oriented, error-tolerant: every problem becomes a `Diagnostic` (1-based line/column, exclusive `endColumn`, consumed directly as Monaco markers) and the bad line is skipped, so half-typed input still renders. Unknown properties are warnings, never errors. Notable rules:
   - Names may contain spaces and hyphens; `-`, `--`, `-->` are connectors only when surrounded by whitespace (`web-01` is a name). `>`, `<`, `<>` are always connectors outside quotes.
   - After `:` in a connection, the rest of the line is the label (connector chars allowed), with an optional trailing `[props]`.
   - Undeclared names referenced by a connection become `implicit` nodes in the group the connection was written in. Edges are resolved after the whole file is read, so declaration order doesn't matter.
   - Text after `{` or `}` on a line is re-parsed as its own segment (single-line groups `G { A, B }`).
2. **`view/view.ts`** — `buildView(diagram, { focus, expandDepth }) → DiagramView`. This is the **recursive drill-down** model: shows the children of the focused group; groups deeper than `expandDepth` become `collapsed`; endpoints outside the focused subtree become `external` nodes; edges are re-attached to their visible representative and merged (the `sources` array keeps the originals).
3. **`layout/eraserLayout.ts`** (default engine) — groups are arranged **inside out**: each container's direct children are laid out as a *flat* ELK graph of the edges between them (declaration order enforced via `forceNodeModelOrder`, which only behaves on flat graphs; cycles broken by `MODEL_ORDER`; `separateConnectedComponents: false` so unconnected siblings stack in a column), the group is sized around them and becomes one box for its parent. Post-passes: `alignSpine` straightens the flow's main path (first non-"no" outgoing edge per node), `alignGroupColumns` turns groups that each own a slot along the flow into equal aligned columns, `placeAnnotations` moves root leaves connected only by dashed/plain lines into a row below. Edges are then routed on final geometry by Eraser's corridor router (`@eraserlabs/layout`, 0.x — failures fall back to straight lines). `layoutView(…, { engine: 'elk' })` keeps the older single compound ELK pass described next.
   **`layout/layout.ts`** — `layoutView(view, opts) → Promise<DiagramLayout>`; the `elk` engine is ELK layered (`INCLUDE_CHILDREN`, orthogonal routing). Output coordinates are absolute; ELK edge coordinates are relative to `edge.container` and are converted. Only the current view is laid out. Text measurement is injected (`measureText`); tests use the char-width estimate, the browser uses a canvas measurer — node sizes must be measured with the same font the SVG renders (`FONT_FAMILY` in `react/theme.ts`).
4. **`react/`** — `DiagramSvg` renders a layout (no outer `<svg>`); `OctoDiagram` owns parse → view → layout, pan/zoom, breadcrumbs, keyboard (Esc/Backspace up, `0` fit, `+`/`-`), and the drill zoom animation. The camera is only re-fitted on level changes or `expandDepth` changes — not on edits — so typing doesn't jump the view. A `fitted` ref tracks whether the camera still shows the auto-fit; while it does, resizing the canvas re-fits, after the user pans/zooms a resize keeps the centre.

## Eraser JSON and the layout corpus

- `eraser/importJson.ts` imports the positioned JSON Eraser generates (Shape / Group / Relationship / Textbox, with `containerId`, relative `points`, `labelPlacement`). `OctoDiagram` renders it as-is when the source starts with `{` (no drill-down). Explicit `bgColor`/`borderColor` become `LayoutNode.style`, applied only in light mode; Eraser's default line color `#1c1c1c` maps to the theme edge color.
- `corpus/NN-name.eraser` are 20 DSL examples; drop Eraser's output next to them as `NN-name.json` / `NN-name.png`. `test/corpus.test.ts` checks every example parses without diagnostics. `http://localhost:5180/?compare` shows octodraw vs Eraser JSON vs Eraser PNG per example. Vite caches `import.meta.glob` results — touch `apps/playground/src/Compare.tsx` after adding corpus files.
- Observed Eraser conventions (corpus 01–07; 04–07 are its classic renderer, which octodraw follows by default):
  - **Node variant** (`chooseNodeVariants`, verified node-for-node by `test/variants.test.ts`): whole diagram is cards when ≥25% of nodes are flowchart shapes or ≥60% have descriptions; otherwise nodes with an icon are bare 50px **icon nodes** with the label below, except flowchart shapes, icon-less nodes, and groups that are ≥half cylinders. Icon nodes are laid out as 50×50 ELK nodes with an OUTSIDE V_BOTTOM label so edges attach to the icon.
  - **Color**: uncolored cards white with near-black outline; colored cards 100-shade fill / 500-shade outline (400 for yellow/lime); groups 500-shade border with 50-shade fill, nested groups inherit and alternate tint/white; nodes never inherit a group's color. Icons monochrome unless the node is colored.
  - **Edges**: 0.75px near-black, filled triangle at the end, open chevron at the start of `<>`.
  - **Layout**: declaration order is kept within groups/layers; flows read top-down by declaration; top-level groups form aligned full-height columns; side nodes linked only by dashed/plain lines sit below; in flowcharts the main path is a straight spine. The eraser engine reproduces these, including `no` branches placed beside their decision on its row (`placeNoBranches`, before `alignSpine`; the spine starts only at nodes nothing points into, so loops back don't bend it).
  - Eraser's JSON comes from its AI and varies run to run (it may add groups, e.g. "Clients" in 07, and 04's layout is broken); treat it as evidence, not ground truth.

## Design system and icons

- **`theme/tokens.ts`** is the single source of visual truth: `lightTheme` / `darkTheme` (color roles, per-scheme `palette` swatches for every DSL color name, typography, radius, 4px spacing, strokes, shadows, motion). Never hard-code colors or sizes in components; add a token. `themeCssVariables(theme)` exposes them as `--od-*` CSS variables, which the overlay chrome (`OctoDiagram` CSS string) and the playground stylesheet consume. `react/theme.ts` maps palette names/raw colors to node/group colors per `colorMode` and keeps brand logos legible in dark mode.
- Layout and renderer must agree on text metrics: `OctoDiagram` passes `theme.text` as `typography` to `layoutView` and measures with `theme.font.sans`; it re-lays out when web fonts finish loading. `DEFAULT_TYPOGRAPHY` in layout mirrors `lightTheme.text` for tests.
- **Icons** accept every name on https://docs.eraser.io/icons (names only, saved by section in `scripts/eraser-icon-names.json`; no Eraser artwork). `pnpm icons` generates `src/icons/generated-core.ts` (curated aliases from `scripts/icon-catalog.mjs`, bundled eagerly) and `generated-full.ts` (all of Eraser's "General" names → Lucide, "Tech logos" → Simple Icons where available; ~875KB, loaded lazily by `loadFullIconCatalog()`, which `OctoDiagram` calls on mount and re-renders via `onIconCatalogChange`). Both are generated — don't edit. Cloud/k8s/networking names (`aws-`, `gcp-`, `azure-`, `oci-`, `k8s-`, `cisco-`, plus `d365-`, `fabric-`, `power-`, `microsoft-`) resolve in `icons/resolve.ts` to a generic glyph picked by keyword rules (`SERVICE_KEYWORDS`) and tinted with the provider color, because the official vendor sets have restrictive terms; hosts can pass an `IconResolver` (`icons` prop) for official artwork. `test/icons.test.ts` asserts coverage of Eraser's list (General >97%, logos >80%, cloud 100%). Unknown names render an abbreviation placeholder.
- **Vendor icon packs** (licensed, preferred): `packages/octodraw/icons/vendor/<provider>/<eraser-name>.svg`, imported by `scripts/import-{aws,gcp,oci}-icons.mjs` (OCI first goes through `scripts/export-drawio-library.mjs`, which renders the draw.io library with the diagrams.net viewer in headless Chrome) and bundled by `pnpm --filter octodraw icons:vendor` into `src/icons/generated-vendor.ts` (lazy, `loadVendorIcons()`). Resolution order: host `icons` → vendor → Eraser artwork (if `iconSet="eraser"`) → open-source catalog. Short aliases (`aws-s3` → `aws-simple-storage-service`, …) live in `resolve.ts`. See `scripts/README-vendor-icons.md` and each provider's `SOURCE.md` for coverage. Future: serve icons per-file from a CDN instead of lazy bundles.
- **Eraser's icon artwork (temporary)**: `packages/octodraw/icons/eraser/*.svg` were downloaded from Eraser's public asset bucket at the user's request as a stand-in until vendor icon packs are bought — read `icons/eraser/NOTICE.md` (no redistribution license; do not present them as octodraw's own). `pnpm --filter octodraw icons:eraser` turns them into `src/icons/generated-eraser.ts` (sanitized inline SVG: `[viewBox, root attrs, body]`, ~1.3MB gzipped, lazily loaded by `loadEraserIcons()`). With `iconSet="eraser"` (the default) they are resolved before the open-source catalog; a host `icons` resolver still wins. They render as `kind: 'inline'` so monochrome icons (Eraser's general set is Lucide, its logos Simple Icons) take the node tint and follow dark mode, while multicolor vendor icons keep their fills. To drop them: delete the folder and generated file and default `iconSet` to `'open'`.

## Animation and streaming

`DiagramSvg` draws every node/group at local (0,0) inside a `Positioned` wrapper whose CSS `transform: translate()` transitions, so re-layouts glide; keys must stay stable (node id, `from->to` for edges). It remembers ids already shown (refs updated in an effect after commit) so only new elements get the `od-enter` / `od-draw` / `od-fade` keyframes (defined in `OctoDiagram`'s CSS, disabled under `prefers-reduced-motion`). `drawIn` reproduces Eraser's AI draw-in: the layout is computed once for the whole diagram (boundaries never move, camera stays put) and `revealCount` shows groups/nodes one at a time in layout order (parents first, declaration order), then edges — components first, arrows last. Remount (`key`) to replay; the playground's Draw in button does this. `streaming` is only a fallback for text whose end is unknown: layout throttled to ~1/s, camera only zooms out when content spills out of view, diagnostics on the unfinished last line dropped. Re-laying out on every streamed chunk made everything shake — avoid it.

Gotcha: the level-entry effect schedules a double `requestAnimationFrame` to reveal content; it must not be cancelled on re-run (only on unmount) — streaming produces layouts faster than two frames and cancelling left the canvas at opacity 0.

Collapse controls: diagrams start fully expanded. `OctoDiagram` keeps a `collapsedGroups` set (passed to `buildView`); hovering a group shows **Collapse | Open** (`GroupActions` in `DiagramSvg`, counter-scaled to stay readable when zoomed out), a collapsed box shows **Show | Open**; "Open" is the drill-down (Eraser's "Expand"). The overlay **Collapse all / Expand all** button collapses every group or clears the set and re-fits the camera.

Gotcha: pointer capture for panning is taken only after the pointer moves >3px; capturing on pointerdown retargets clicks to the `<svg>` and breaks double-click-to-drill.

## Language extras

All 11 Eraser flow chart shapes are drawn by `nodeOutline` in `DiagramSvg` and sized by `SHAPE_SIZING` (layout); their true outlines are passed to the router (`outlineFor` in `eraserLayout.ts`) so arrows meet the drawn edge. `legend` is laid out by `placeLegend` (outside the diagram: top corners beside it, bottom corners below, `left`/`right`/`top`/`bottom` centered) and drawn by `LegendBox`. `link:` nodes get a badge and call `onLinkClick` (default opens http(s) in a new tab). `typeface` maps to `theme.font.{sans,mono,rough}` via `fontFamilyFor`; layout measures with the diagram-wide face. The parser defaults `typeface` to `clean` (Eraser's docs say `rough`, but its renders are clean) and warns on unknown property values.

## Maps (flows, filters, details)

octodraw extensions to the DSL: `flow Name { A > B: caption }` blocks (parser `flow` scope; steps go to `diagram.flows`, never to edges; unknown nodes warn) and `team` / `tech` / `tags` node properties. `maps/maps.ts` is pure: `facetValues`, `filterEmphasis`, `flowEmphasis` (map diagram ids to the visible representative via `visibleRepresentative`, so collapsed groups light up), `connectionsOf`, `ancestorsOf`. `OctoDiagram` owns the flow player (bottom centre), the Filter menu and chips, and the details panel; `DiagramSvg` takes `emphasis` (dims everything outside it with `.od-dim`, accents `current` with a marching edge and pulsing `FocusRing`) and `selected`. Clicking a node selects it (link badges open links on their own); clicking empty canvas (not a pan) clears it. Toolbar menus close on outside press / Escape.

## ERD, sequence and BPMN diagrams

`dsl/detect.ts` `detectDiagramType` picks `flow` | `erd` | `sequence` from the code (sequence-only statements/blocks, typed columns or `table.column` relationships, `notation`); `OctoDiagram`'s `type` prop overrides. `dsl/erd.ts` / `dsl/sequence.ts` are separate error-tolerant parsers (reusing `stripComment`, `findClosingBracket`, `splitOutsideQuotes`, `unquote` exported from `dsl/parse.ts`). `erd/erd.tsx` lays tables out with ELK and routes links itself (from column rows, per-gap lanes) with crow's-foot or Chen markers; `sequence/sequence.tsx` is a synchronous column/row layout with activations, blocks and autoNumber. For these types `OctoDiagram` hands the camera a size-only `DiagramLayout`, renders `ErdSvg` / `SequenceSvg` instead of `DiagramSvg`, hides architecture-only controls, and `renderDiagramSvg({ body })` exports them. Draw-in reveals tables then relationships / participants then messages / BPMN elements then connections (the timer is keyed on the box count and restarts on StrictMode's extra mount, so re-layouts can't freeze it). ERD: clicking a table focuses it (unrelated tables and links dim); `layoutErd({ collapsed })` keeps only key columns plus an "N more columns" row (header chevron per table, Collapse all in the toolbar). Sequence: a step-through player (`seqStep`, arrow keys) accents the current message and dims later ones.

BPMN (Eraser's swimlane syntax) is the architecture syntax with `type: activity|event|gateway` on flow objects; top-level groups are pools, their groups lanes. `detectDiagramType` returns `bpmn` when a `type:` property appears. `bpmn/bpmn.tsx` `layoutBpmn` is synchronous: rows per lane (a pool without lanes is one row; loose elements get a row on top), columns by longest path ignoring loops back, same lane+column stacks, events/gateways carry their label below; edges are routed by the corridor router (`routeEdges` with event/gateway outlines). `BpmnSvg` draws pools/lanes with vertical name strips, rounded activities, start (thin) / end (thick) events and X gateways.

`export/source.ts` `renderSourceSvg(source, { theme, placements? })` turns code of any type straight into SVG (no component; works on a server); the canvas template gallery uses it for previews (`OctoCanvas templates` prop overrides the built-in boards). `styleMode watercolor` draws two filtered, wobbly, grainy washes (`WatercolorDefs`, `Wash` in `DiagramSvg`) under nodes, groups and icon nodes, with faint outlines. Dragging a diagram node snaps it to other boxes on the level (`snapBox` from the canvas model, guides in layout coordinates; Alt disables).

## Export

`export/svg.ts` `renderDiagramSvg` renders a layout to a standalone SVG string with `react-dom/server` (no hover actions, `animation: 'none'`, theme background, optional title, optional `fontCss`) — pure, usable on a server. `export/browser.ts`: `collectFontCss` inlines the page's Latin `@font-face` files as data URLs (browsers normalize `unicode-range` to `U+0-FF`), `svgToPng` (canvas), `svgToPdf` (jsPDF + svg2pdf.js, dynamically imported; embeds the TTF fonts registered with `registerPdfFonts` — svg2pdf matches by family name and a style key like `normal`/`bold`/`500normal`; the playground registers Inter 400–700 and JetBrains Mono from `apps/playground/public/fonts`, OFL-licensed), downloads/clipboard, `embedSnippets`. `export/eraserJson.ts` writes Eraser element JSON (round-trips through `importEraserJson`) and Eraser XML (children nested in groups). `OctoDiagram` exposes all of it through a `ref` handle and an overlay Export menu (`exportMenu`, `share` props); exports use the current view (drill level, collapsed groups). pnpm 11 needs `allowBuilds: { core-js: false }` in `pnpm-workspace.yaml` (jspdf dependency).

## AI

octodraw never calls a model and holds no keys; the host supplies a `DiagramModel` (`({ system, messages, signal }) => AsyncIterable<string> | Promise<string>`), typically a fetch to its own server route. `ai/prompt.ts` `diagramSystemPrompt` is the syntax reference for models (all three types, or one). `ai/generate.ts`: `extractDiagramCode` (works on partial streamed text), `validateDiagram` (picks the parser by type; empty diagrams are errors), `buildUserMessage` (inlines referenced figures, the first one is edited), `generateDiagram` (streams, validates, sends parser errors back for `maxRepairs` rounds, returns `messages` for follow-ups). `ai/attachments.ts`: files given to the assistant (`attachmentFromFile`; text inlined with a per-kind hint for Terraform, CloudFormation, Kubernetes, Compose, OpenAPI, SQL/Prisma/GraphQL (→ ERD) and source code; images become `ContentPart` image parts, so `ModelMessage.content` is `string | ContentPart[]` and host adapters map parts to their model's format — the playground maps them to Claude image blocks). Whole folders (`attachmentsFromFolder`: skips dependencies/build output/lock files/binaries, ranks infrastructure and schemas first, caps 40 files / 300k chars), `.zip` archives (`filesFromZip`, fflate loaded lazily, size-capped) and GitHub repositories (`attachmentsFromGitHub`: tree via the GitHub API, then only the chosen files from raw.githubusercontent.com; `githubToken` prop for private repos) all feed the same attachment list. `ai/useDiagramChat.ts` holds conversation state (`initialMessages` / `onMessagesChange` let hosts save it; `historyFromMessages` rebuilds model context); `ai/DiagramChat.tsx` is our own chat panel (figure chips, `@` picker, starters, stop), styled from `--od-*` variables. `OctoDiagram`'s `onAskAi` prop adds an "Ask AI" toolbar button. The playground (`apps/playground/src/ai.ts`) has a keyword demo model and a direct browser call to Claude through `@anthropic-ai/sdk` with a user key (`dangerouslyAllowBrowser`; playground only); streamed code shows in the editor and the finished diagram replays with `drawIn`.

## Hand placement

`layout/arrange.ts` `arrangeLayout(view, autoLayout, placements)` applies hand placements after the automatic layout: placed nodes take their stored top-left (and size, for groups and cards), unplaced descendants move with their group, groups grow to keep children inside, then edges are re-routed and the legend re-placed (`layout/route.ts`, split out of `eraserLayout.ts` so it loads without ELK). If anything ends up above/left of the padding the whole drawing is shifted and `layout.offset` records it (layout = placement + offset). Placements are `ViewPlacements` keyed by drill level (`placementKey(focus)`, '' = top) and node id, stored by the host next to the code (canvas figures keep them on `FigureItem.placements`), so the code stays Eraser-compatible. `OctoDiagram` (`arrange`, `placements`, `onPlacementsChange`): dragging a node (>3px) moves it with live re-routing (animation off during the drag), a selected group or card shows a corner `.od-resize` handle, "Reset layout" clears the level. Groups are selectable by a single click.

## Free-form canvas and figures

`canvas/model.ts` is the canvas document: `{ version: 1, items }`, a flat list in stacking order of `shape` (rectangle/ellipse/diamond, optional label), `text`, `pen` (points normalized 0–1 to the box so resizing scales them), `line` (start/end `Endpoint`s, optionally attached to an item via `item`, kept on the item's outline by `resolveLines`), `icon` and `figure` (diagram `source`, `autoSize` until the user resizes it). All edits are pure functions (`moveItems`, `resizeItem`, `reorderItems`, `duplicateItems`, `removeItems` detaches lines, …) so the document can later be synced with Yjs. `useCanvasHistory` gives hosts undo/redo; `silent` changes (a figure growing to fit its diagram, code typed in the editor) aren't undo steps.

`canvas/OctoCanvas.tsx` is controlled (`doc` + `onChange`). Items are absolutely positioned elements inside one world `div` transformed by the camera, so DOM order is z-order and figures (HTML) mix with shapes (SVG). Gestures attach window listeners on pointerdown (no pointer capture, so double-click still targets items); a drag renders a `preview` document and commits once on release. Each figure is an embedded `OctoDiagram` (`embedded`: always fits its box at ≤1:1, no wheel/drag capture, compact padding; `chrome` only when entered; `onContentSize` drives auto-size). Figures are inert (`pointer-events: none`) until entered with double-click/Enter; Escape (when the diagram didn't consume it) leaves. The camera re-fits as figures size themselves until the user moves it; inserted figures go to a free spot (right of everything when the view centre is taken) and the camera follows them. Also: `sticky`, `image` (data URL unless the host passes `onUploadImage`), `frame` (device outlines drawn by `DeviceOutline`; inserted at the back; moving one carries the items inside it) and `code` items; `text` has `bold`/`align`. `doc.comments` holds threads pinned to an item (offset from its top-left) or a canvas point; `canvas/Comments.tsx` draws pins and the thread popover in screen space; authors come from the `user` prop. Moves, resizes and new shapes snap to other items' edges/centres (`snapBox`, Alt disables) and draw guides; a multi-selection has group handles (`resizeItems`). "To diagram" (`selectionToSource`) replaces boxes, stickies, icons and the arrows between them with a figure. `canvas/export.tsx` `renderCanvasSvg` renders items as SVG and nests each figure's own exported SVG; the handle's `exportSvg`/`exportPng` collect those from the figures' OctoDiagram refs. The corner Export menu downloads PNG/SVG/PDF or copies PNG/SVG (canvas or selection); a selected figure's bar has its own Export menu that calls that figure's OctoDiagram handle (every diagram format). `.occ-root` is a size container (`container: occ / size`), so `@container occ` rules adapt the chrome to the host pane, not the viewport: under 640px the tool rail runs along the bottom (above the corners) and the selection bar wraps at the top; handles grow on coarse pointers. Editors opened by a click must keep focus: the click's pointerdown default is prevented and focus is re-applied next frame. The tool rail (`canvas/ToolRail.tsx`, 2026-10-30, Eraser's) runs down the left edge from the top: separate cards on a thin line — Insert (+, / or ⌘K; × while open) · AI (only with `onAskAi`, ⌘J) · Select V, Rectangle R, Ellipse O, Arrow A, Line L, Pen D (P too), Text T, Icon I (opens the Insert panel on its Icon page) · Figure F (drag a box → an empty figure, `source: ''`) and Comment C; corner key letters and a tooltip it renders itself. Diamond, sticky (S) and pan (H / Space) are off the rail. The selection bar (`SelectionBar`) docks at the bottom centre like the element toolbar: lifted above the selection when it would cover it, at the top when there's no room. `InsertPalette` (+, ⌘K or /) is a panel beside the rail: a category page (Diagram as Code, Diagram Catalog, Shape, Icon, Device Frame, AI Chat when wired; tiles Figure / Code Block / Image), each category its own page with a back arrow, and typing on the top page searches everything; it lists figure templates and whole-canvas templates (`canvas/templates.ts`: `FIGURE_TEMPLATES`, `CANVAS_TEMPLATES` built fresh at the origin and cloned to a free spot), shapes, icon search and "draw with AI"; an empty canvas shows the canvas templates as a gallery. Items may carry `rotation` (degrees about the centre; not lines or figures): the box stays unrotated and `itemAt`, `itemsInBox`, `boundsOf`, `outlinePoint`, comment pins and export account for it; `rotateItems` turns a selection about its centre and `resizeRotatedBox` resizes in the item's own frame. Optional style fields (added for the tldraw conversion; all round-trip through collab, versions, copy/paste and are checked by `isCanvasDocument`): `LineItem.bend` (signed distance from the chord midpoint to the curve midpoint along n = (−dy, dx)/len of end − start; drawn as a quadratic Bézier with control mid + 2·bend·n; `lineGeometry` gives ends/control/mid, attached ends of a bent line aim at the control point; `lineBounds` fits the box to the curve; the selected line's middle handle sets it via `bendThrough`, snapping to straight near 0), `Endpoint.anchor` (0–1 point in the attached item's unrotated box the end aims at; `anchoredEnd`: if the anchor is inside the gap-grown outline and the other end outside, the end is where the segment enters the outline, otherwise the anchor itself; re-attaching an end drops it), and on shapes `align`/`valign` (label placement, padding from `shapeTextPadding`), `dashed` (the line dash, `DASH`) and `fill` (`tint` default, `none`, `solid` = swatch `solid`/`onSolid`, uncolored = `node.stroke` with canvas-colored text) — `shapeColors(theme, color, fill)`. The playground is canvas-first: the code pane edits the selected figure, the assistant references any figure and its results update or add figures.

## Collaboration

`octodraw/collab` (separate package entry so non-collaborating hosts don't bundle Yjs) binds the canvas to a shared `Y.Doc`. `collab/sync.ts`: items live in `Y.Map('octodraw.items')` as one `Y.Map` per item with one entry per field (concurrent edits to different items/fields both survive; values are last-writer-wins per field), stacking order is a float `z` per item (`assignZ` keeps numbers still in order, fits new/moved items between neighbours; ties by id), figure `source` and code-block `text` are `Y.Text` updated with a minimal middle diff (`updateText`) so two people can type in the same figure; comments are `Y.Map('octodraw.comments')` of thread JSON. `writeCanvas`/`readCanvas` are pure; `CanvasSync` keeps a live `doc` (unchanged items keep object identity), writes local edits with a tracked origin (silent changes use an untracked one) and owns a `Y.UndoManager`, so undo reverts only this user's edits. It must survive React StrictMode: `useCollaborativeCanvas` calls `connect()` in its effect and `destroy()` in cleanup. Presence uses y-protocols `Awareness` (`user`, `cursor`, `selection`); `OctoCanvas` takes `peers` (draws cursors and coloured selection outlines with name tags) and reports `onPresenceChange` (cursor throttled to a frame). The host owns the transport and persistence (y-websocket, Hocuspocus, …) and calls `seedCanvas` only after its provider has synced. `connectBroadcastChannel` syncs tabs of one browser for demos: the playground's "Go live" opens `?room=<id>` (`apps/playground/src/live.ts`, per-tab guest name, room state saved in localStorage). The playground `CodeEditor` applies outside changes as minimal Monaco edits so cursors survive remote typing. Note background tabs throttle `requestAnimationFrame`, so a hidden tab's figures re-render when it becomes visible.

Comment threads are `Y.Map`s with messages in a `Y.Array` (matched by id, so simultaneous replies all survive); shape, sticky, text and line labels are `Y.Text` like figure code; `assignZ` renumbers everything when two neighbours run out of float precision. Presence also carries `view` (the visible canvas box; `OctoCanvas` `following` copies a peer's view until the user pans/zooms, then calls `onStopFollowing`) and `code` (text offsets in the figure code editor; the playground `CodeEditor` draws peers as Monaco decorations — create decorations per editor instance, StrictMode makes two).

## Version history

`canvas/versions.ts`: a `CanvasVersion` is a full JSON copy of the document (`at`, optional `name`, `author`, `auto`). Hosts provide a `VersionStore` (`list` newest first, `save`, `remove`, `rename`, `subscribe`); built in are `localVersionStore(key)` (localStorage, trims automatic versions past a limit, keeps named ones) and `yjsVersionStore(ydoc)` in `octodraw/collab` (a `Y.Map` in the shared doc, so collaborators share history; it grows the Y.Doc, so long histories belong in the host's database). `useVersionHistory` auto-saves while the canvas changes when nobody using the same store saved within the interval, and `restore` saves the current state first and returns the old document for the host to pass to `onChange`, so a restore is a normal edit: it syncs and can be undone. `VersionHistory` is the panel (current + versions by day with +added/−removed/edited counts, name/rename/delete, restore). Previewing renders the version with `OctoCanvas readOnly` (pan/zoom/open figures only; no rail, selection bar, comments or edits); hosts must not write while previewing (the playground routes every write to the live document).

Presentation mode: `canvas/present.ts` `presentationSlides(doc)` gives the slides — figures and device frames in reading order (rows by top edge, then left to right; a figure inside a frame belongs to the frame), or the whole canvas when there are none. `OctoCanvas` "Present" (corner button, `present()` / `stopPresenting()` handle methods, `onPresentChange`) goes full screen (`requestFullscreen`; leaving full screen ends it), forces read-only, hides the chrome, glides the camera (`.occ-world-glide` transition) to `fitBox(slide, 2)`, replays a figure slide's draw-in (an internal draw-in nonce overrides the `drawIn` prop while presenting), re-fits on resize, and restores the camera afterwards. Keys: → ↓ Space PageDown / ← ↑ PageUp / Home End / Esc; a sideways touch swipe changes slide. The bottom bar fades after 2.5s without pointer movement. Collaborators can follow the presenter with the existing follow feature. `doc.presentation` (`order`, `hidden`, `notes`; synced through the `octodraw.meta` Y.Map) customises the deck: `presentationSlides` puts saved order first and new slides after in reading order, flags hidden ones (`visibleSlides` drops them); `moveSlide` / `setSlideHidden` / `setSlideNotes` are pure. The Slides panel edits them; while presenting N shows notes and L is a laser pointer (screen-space fading trail; presence `laser` makes collaborators see a red dot).

The presenter view is a second window (`window.open`) rendered with `createPortal` from the same component state (no cross-window messaging; its own `PRESENTER_CSS`), showing notes, next slide, elapsed time and controls; its arrow keys drive the presentation, and it closes when the presentation ends. Sequence participants can be dragged sideways (placements store their x; `layoutSequence({ order })`), and BPMN elements dragged within their lane (`layoutBpmn({ placements })` clamps to the lane and re-routes). BPMN also takes `type: subprocess|data|store` (octodraw extensions; lines to data are dotted associations) and `attached: <task>` on events (boundary events, placed on the task's bottom edge; their hosts reserve room below). Copy/cut put the comments pinned to the copied items on the clipboard and `cloneWithComments` re-pins them on paste. `ghosts` (item ids) fades items; version previews add the items a version removed back as red-outlined ghosts.

Figures more than a screen away from the view are parked (dashed placeholder, no OctoDiagram mounted; `figureLive` keeps selected, opened, drawing-in and presented figures live); canvas export renders parked figures with `renderSourceSvg`. The playground's `?figures=N` loads a generated N-figure canvas (not saved) for performance checks. `highlights` (item id → colour) outlines items; the playground uses it to show what a previewed version added/edited. Read-only views never show a selection. Presence carries `following` + `followingSince`; of two people following each other the earlier follower stops. OctoDiagram shows details panels for ERD tables (columns, relationships) and sequence participants (messages); in canvas figures only when opened and ≥640 wide. Comments: `people` lists who can be @mentioned (picker on "@" in the thread popover), messages store `mentions` (ids; `mentionsIn` keeps only names still in the text), mentions are highlighted, and `onMention({ thread, message, mentioned })` lets the host send notifications. ERD tables are draggable (`arrangeErd` re-routes synchronously; placements under key ''). BPMN gateways take `gateway: exclusive|parallel|inclusive|event`, events `event: message|timer|error|signal` (octodraw extensions); events with both incoming and outgoing connections are intermediate (double ring) and connections between pools are message flows. ERD, sequence and BPMN renderers accept `styleMode` (watercolor washes via the exported `Wash`/`WatercolorDefs`).

On small containers (<640px) an opened figure is shown full size in an `.occ-focus` overlay (its own pan/zoom) instead of inside the scaled world, and `OctoDiagram`'s chrome switches to icon-only tools via `@container od` (rules must come last in its CSS string to win over the base rules).

Known gaps are tracked in `BACKLOG.md`; add to it whenever something is left out.

## Element toolbar (2026-10-30)

Inside a diagram, selecting boxes, groups, icon labels or arrows shows a toolbar docked at the bottom (`react/ElementToolbar.tsx`, popovers in `react/toolbar/`) whose every control rewrites the DSL source — no separate style store. It appears only when the host passes `onSourceChange(next, { label, renamed? })` (plus `chrome`), for flow diagrams; selection is `{ kind: 'node'|'edge'|'label', ids }` (controlled via `selection`/`onSelectionChange` optionally). The decision logic is pure and tested in `react/toolbar/actions.ts` (`toolbarControls`, `actionToEdits`, `runToolbarAction`). Edits come from `dsl/edit.ts` (`setNodeProperty`, `renameNode`, `declareNode`, `deleteNode`, `setEdgeProperty`, `setEdgeLabel`, `setEdgeConnector`, `reverseEdge`, `deleteEdge`, `applyEdits` — pure, all-or-nothing, refuse with a reason), which use `parseDiagramWithSpans` (exact positions of names, `[props]`, connectors, labels, braces). Edge ids are positional; restyling one arrow of a shared line (`A > B, C`, chains) splits it out. "Edit text" renames everywhere, or sets `label` when the box has one. New optional style properties (defaults = old look, guarded by `test/render-baseline.test.ts`): nodes/groups `textSize textAlign textColor iconSize border strokeWidth`; edges `line strokeWidth labelSize routing startArrow endArrow` — layout and renderer share `layout/style.ts`. Canvas figures pass `onSourceChange` when opened and editable (`onFigureSource` in OctoCanvas: one undo step; a rename also moves hand placements via `renamePlacements`). Canvas items gained `strokeColor/fillColor/textColor`, `strokeWidth`, `strokeStyle`, `font`, `italic`, `opacity`, line `startHead/endHead/route` (elbow), a selection bar with sub-menus (`canvas/SelectionBar.tsx`) and a right-click menu (`canvas/ContextMenu.tsx`). ERD and sequence diagrams (`onSourceChange` + `chrome`, separate `otherEditable` flag in `OctoDiagram`; details panels and focus dimming are off while it's on) use the same bar through its `delegate` prop: `toolbar/erd.ts` / `toolbar/sequence.ts` are the pure decisions (`erdControls`, `runErdAction`, `sequenceControls`, `runSequenceAction`, prune helpers) and `toolbar/ErdSequenceControls.tsx` builds the delegates. Tables and participants are `node` selections by name, relationships (`r<i>`) and messages (`m<i>`, the order of `SequenceLayout.messages`) `edge` selections; `ErdSvg` / `SequenceSvg` take `selectedLinks` / `selectedMessages` and `onSelectLink` / `onSelectMessage` (wide invisible hit lines with `data-edge-id`). Table: Edit name · Icon · Colour · Key columns · ⋯ (Add column, link, delete). Relationship: Edit label · Cardinality (crow's-foot or Chen previews) · Colour · ⋯. Participant: Edit name · Icon · Colour · ⋯ (link, "Delete with N messages"). Message: Edit label · Colour · Line (call `>` / return `-->`) · Direction (named after the participants) · ⋯; several messages get Direction too (Forward as written / Back / Both ways, applied to each, the whole batch refused naming the message that can't, e.g. a return both ways). Selections also take `kind: 'column' | 'block' | 'activation'` (`SelectionKind` in `actions.ts`; hosts' `onSelect` only hears `node` / `label`). ERD columns are `column` selections by `table.column` (`ErdSvg` `selectedColumns` / `onSelectColumn`, rows carry `data-column-id`, accent row highlight; the header still selects the table): Edit name (`renameColumn` renames the line and every `table.column` reference; no spaces) · Type ▾ (string, int, float, boolean, date, datetime, uuid, json, the current one, Other… free text; quoted when it has spaces) · Key ▾ (pk / fk / unique / nullable switches, written as words after the type — a flag needs a type, else refused) · ⋯ (Add column below, Delete column — refused while a relationship uses it, "Used by N"). A column only named in relationships gets a line in its table when typed; Add column writes `column`, `column_2`… `string` below the column / at the end of the body, giving the table a body or a declaration (before its first use) when it has none. Positions come from `ErdSpans.columns` (name, type and flag words per column line). Sequence blocks are `block` selections (`b<n>`, the order blocks open in; `SequenceSvg` `selectedBlocks` / `onSelectBlock`: the frame stroke and the label tab are clickable, `data-block-id`; blocks may now carry `icon:`, drawn in the tab): Edit label · Kind ▾ (loop/alt/opt/par/break; alt ⇄ par rewrites `else` ⇄ `and`; a block with sections can't become a one-section kind — refused with a reason rather than dropping the `else` messages; the menu marks those kinds) · Colour · Icon · ⋯ (Delete block, keep messages = `unwrapBlock`, removes the frame lines and dedents; Delete block and N messages = `deleteBlock`, keeping a declaration for participants first written inside and refused when an activation crosses the block's edge). Activation bars are `activation` selections (`a<n>`, the n-th `activate`; `sequenceActivations` pairs each with its `deactivate`, innermost first, and `SeqActivationLayout.id` matches): a "<participant> active" tag · ⋯ Delete (`deleteActivation` removes both lines, keeping a declaration when the `activate` is where the participant is first written). Spans: `SequenceSpans.blocks` (each opening / section line with keyword, `[props]` and the line of its `}`). The step-through player hides while the toolbar shows. "Key columns only" (toolbar switch, header chevron, Collapse / Expand all) is saved with the hand placements under the reserved level `ERD_COLLAPSED_KEY` (`'#erd-collapsed'`, `{ table: { x: 0, y: 0 } }`; `erdCollapsedFrom` / `withErdCollapsed` in `erd/erd.tsx`), so canvas figures keep it in `FigureItem.placements` with no model change, `renamePlacements` moves it on a table rename, and `renderSourceSvg` draws it (it now also applies ERD hand placements). OctoDiagram mirrors it in state, so hosts that don't store placements still toggle. Connector rewrites keep the spacing as written (`a.id<b.id` → `a.id<>b.id`, `A>B` → `A<>B`); dashed connectors (`-`, `--`, `-->`) get a space on any side that has none. Edits are `dsl/edit-erd.ts` and `dsl/edit-sequence.ts` (pure, all-or-nothing `applyErdEdits` / `applySequenceEdits`, shared text helpers in `dsl/edit-text.ts`) over `parseErdWithSpans` / `parseSequenceWithSpans`. Column order (first appearance) never changes: a participant styled only in messages gets a declaration before its first use (after it when the other end is new on that line too), deleting a message keeps a declaration for participants first written or styled there, and a return pointed back swaps its ends (declaring the first one when both are new). A message colour without a label is written `A > B: [color: red]` (without the colon the bracket belongs to B). Renamed tables / participants keep their collapsed state and own placements. Remaining gaps (sections not selectable, flags other than pk/fk not drawn, …) are in BACKLOG.md.

BPMN diagrams get the toolbar too (BPMN is the flow syntax, so the same `dsl/edit.ts` edits apply; `ToolbarContext.bpmn` switches `toolbarControls` / `actionToEdits` to `react/toolbar/bpmn.ts`, whose UI is `react/toolbar/BpmnControls.tsx`). `BpmnSvg` takes `selection`, `onSelect`, `onSelectEdge`, `zoom`: elements, pools and lanes are `node` selections by DSL name (shift-click for several), connections are `edge` selections by the layout's view edge ids (invisible wide `data-edge-id` hit paths), drawn with the accent outline / stroke. Element: Edit text · Type (activity / event / gateway / subprocess / data object / data store) · Gateway kind or Event trigger · Colour · ⋯ (Attach to task… for events, description, link, delete). Pool / lane: Edit title · Colour · ⋯ (Add lane on a pool / Add lane below on a lane, Add task, delete keeping or with contents). Adding uses `dsl/edit.ts` `addGroup(source, parent|null, name, props?, { position?, after?, wrapExisting? })` and `addChild(source, group, line, { position?, after? })` (indented like the group's children, one-line groups expanded, refused on errors / a missing `}` / a line that wouldn't parse): a new lane is `Lane N {}` at the pool's end or right after the lane (N = first free name); a pool with steps but no lanes first wraps them in `Lane 1` (its steps are drawn in its first lane); Add task writes `Task N` (default activity) into the lane, or a pool's first lane. Both select the new element and open its name editor (`PlannedEdits.edit` → `ToolbarResult.edit` → OctoDiagram's `pendingEdit`). Empty lanes keep the 96px minimum row height. Sequence flow: Edit label · Colour · Line (solid / dashed) · Reverse · ⋯; message flows and data associations show a fixed "Message flow" / "Association" tag instead of Line. Defaults are written as no property (activity, exclusive, no trigger). A type change is one `applyEdits` batch that drops `gateway:` / `event:` / `attached:` the new type can't have and detaches boundary events from a task that stops being a task (deleting a task does the same); because `detectDiagramType` needs one `type: activity|event|gateway`, the last one is kept written out. Deletes (Delete key or ⋯, elements, pools, lanes) guard the same way: when they would remove the last typed one, `type: activity` is written on a remaining plain element (first one in a pool preferred), or the delete is refused when only extension types (subprocess / data / store) or nothing would be left. `bpmnAsDiagramLayout` lets OctoDiagram place the bar and the text editor on BPMN boxes.
